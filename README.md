## 先说人话：这玩意儿是干嘛的

你大概看过不少"副业课""一人公司训练营"。它们大多有个隐藏前提：**你得先会写代码、先搭爬虫、先搞自动化**。

可现实中想搞副业的人，十个里有八个是文科生、是上班族、是根本不想碰键盘敲程序的人。那些课对他们来说，门槛高得离谱，学完还是不会干。

这个系统就是给这类人做的：**找案例、读内容、拆解、推送，全自动**。你唯一要做的，就是每天打开飞书，看今天又挖到了谁、人家是怎么赚钱的。不用装任何软件，不用懂一行代码。

## 为什么这份情报"值得抄"（重点）

市面上的"赚钱情报"大多有一个通病——**它们自己就是卖铲子的**。

> 19 世纪美国淘金热，真正稳赚的不是淘金的，是**卖铲子给淘金客**的人。今天很多"副业导师""一人公司教练"，就是卖铲子的：他们不靠自己的产品赚钱，靠"教你怎么做一人公司"收学费。

问题在哪？**模仿卖铲子的人，你学到的只是"怎么继续卖铲子"**——也就是去教别人赚钱。这路不是不能走，但它和你最初想"做点自己的小生意"完全是两码事。

这个系统**硬剔除卖铲子的人**。它只推一类人：

- 靠**真实的产品和服务**活下来的一人公司；
- 做内容 / 自媒体拿品牌合作、卖自己的信息产品、做付费社群、做产品化服务 / 代运营的实干派；
- 一句话：**自己下场干活赚钱的人，不是教别人赚钱的人。**

前者能模仿（你照着他的获客和变现路径做就行），后者模仿了也是去卖课。这，就是这份情报和别家最大的不同。

## 它会自己"长大"：越推越准、越推越广

普通情报系统是死的——你喂什么，它吐什么，永远就那点料。

这个系统会**自己找水源**：

- 每次推送，它都顺手去**发现一批新的内容源**（新的公众号、新的博主、新的 RSS）；
- 这些新源会被收进名单，之后持续追更；
- 你每收到一次推送，它的"情报网"就比前一天大一圈。

今天可能挖到 10 个案例，跑一个月，它的水源已经比刚开始丰富了好几倍。**它不是在重复旧内容，是在不断长出新案例。**

## 每天推给你什么

系统分两个模块，各推一张飞书卡：

| 模块 | 每天产出 | 说人话 |
|------|----------|--------|
| 🔍 **操盘手拆解** | 1–2 人 | 把一个"闷声赚钱的个体户"的生意拆开：做什么、客户从哪来、具体怎么操作 |
| 💡 **赚钱机会挖掘** | 约 10 条（国内 + 国际按内容质量动态分配，不硬性规定各 5 条） | 用「四维度 + 三否决」筛出能复刻的真机会，**凡是卖铲子的一律不要** |

## 打分不靠 AI 拍脑袋

早期版本是直接问 AI「这条值几分」。问题很明显：同一篇文章今天问是 0.8、明天问是 0.6，两条机会之间也没法比——**这不是打分，是感觉**。

现在改成 **「AI 只做观察，公式做判断」**：

1. AI 不许给总分，只回答 **11 个能从原文看出来的事实型小问题**，每个 1–5 分，每一档都有明确定义。
   比如「单笔收费」：5 = 一单 ≥1 万元，3 = 300–2000 元，1 = 低于 50 元。
2. 这 11 个分数怎么加权、什么情况下一票压制，**全部写死在 `scoring.py` 的公式里**。

打分框架不是我自己编的，来自两套公开成熟的方法，按"完全不会写代码的人"重新配了权重：

- Josh Kaufman《The Personal MBA》**十项经济性评估**（紧迫度 / 市场规模 / 定价潜力 / 交付成本 / 独特性 / 上市速度 / 前期投入 / 追加销售 / 长青度）
- 独立创业圈的 **BB Score**（10 因子加权 0–100）

最后你在卡片上看到三个数：

| 指标 | 含义 |
|------|------|
| 💰 **商业化潜力** 0–100 | 这门生意本身值不值钱（跟你会不会做无关） |
| 🛠 **可行性** 0–100 | 你这个不会写代码的人，能不能真的落地 |
| 🎯 **适合你启动指数** 1–10 | 综合排序，一眼看出今天最该动手哪条 |

还有几条**一票压制**规则，防止总分虚高掩盖致命短板：

- 需要写代码 → 最高 3 分
- 疑似卖课 / 卖铲子 → 最高 3 分
- 没写清客户从哪来 → 最高 6 分
- AI 没按格式给全打分依据 → 最高 4 分（宁可漏推，不可虚高）

> 校准过一次：全部打中位数（每项 3 分）得 5 分，不是 6 分。平庸的机会就该看起来平庸。

## 每条机会都附一份"可抄模板"

光看懂没用，得能动手。所以每条机会下面都有：

- **卖给谁** / **卖什么** —— 一句话说清生意是什么
- **第一步** —— 今天就能做的那个动作（不是"研究一下市场"这种废话）
- **复制给 AI 的第一句话** —— 直接粘进 ChatGPT 就能用的提示词
- **成本与周期** —— 要花多少钱、多久能见水花

## 同一件事被反复讲到，才是真信号

日报天然是"当天即焚"的：今天推的机会，一周后另一个来源又讲了同一件事，你根本看不出来。

系统现在有一个**跨天机会库**（`storage/opportunity_library.json`）：

- 给每条机会算一个「主题指纹」（基于"卖给谁 + 卖什么"），换个说法讲同一件事也能认出来；
- 卡片上直接标注 **🔁 第 3 次出现 · 已被 2 个来源印证**；
- 日报开头还有一块 **「本周反复出现的方向」**。

一个机会被不同来源、在不同天里反复讲到，比任何评分都更能说明它真实存在。

## 你点的「想做 / 没兴趣」，它收得到

每条机会下面有两个按钮：👍 这条我想做 / 👎 没兴趣。

**先说清楚原理**：飞书群机器人的 webhook 是**单向**的——只能往群里发，收不到你点了什么。想真正接收按钮回调，得注册飞书应用 + 提供一个公网回调地址 + 常驻服务器，对这个"零服务器"的项目来说太重了。

所以换了个不用服务器的办法：

1. 点按钮 → 打开一个**已经填好内容**的 GitHub Issue 页面（标题、标签、机会编号都预填好了）；
2. 你再点一下"提交"，就完成反馈；
3. 第二天运行时，系统通过 GitHub API 把这些 Issue 读回来，调整排序。

调整幅度**刻意做得很小**（±1~2 分）：点过"想做"的方向以后会往前排，点过"没兴趣"的往后压。不会因为你点了一两次，明天推送就完全变样。

## 内容从哪来

- **国内**：微信公众号（按号名定向监测更新）、B站、中文搜索、精选中文 RSS
- **国际**：Starter Story / Side Hustle Nation 等 RSS，以及 Reddit、YouTube
- **X（推特）**：走 X 网页端自身的接口抓取，需要配 `TWITTER_COOKIES`（见 `.env.example`）。**不配就自动跳过，不影响其它源。**
- **侦察兵**：每天自动挖新的「写一人公司 / 本身是 OPC」的号，列入名单持续追更（这就是它"长大"的方式）

> 监测的推特账号是**筛过的非技术向创作者**（内容创业、信息产品、产品化服务），刻意排除了 indie hacker / SaaS 开发 / 程序员博主——那些人的路子对不会写代码的人没有参考价值。

### 🅱️ 路线 B：想自己部署（技术向，可选）

如果你有自己的 AI Key 和飞书机器人，也可以把这套系统 fork 过去自己跑。步骤：

```bash
git clone https://github.com/wsjxphz-png/opc-digdaily.git
cd opc-digdaily
python -m venv .venv && .venv/Scripts/activate   # Windows；mac/Linux 用 source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env                              # 填入 FEISHU_WEBHOOK_URL 与 AI_API_KEY

python main.py --dry-run                          # 先演练：跑完整流程，但不推群、不写历史
python main.py --once                             # 确认没问题再真跑（会真实推送到飞书群）
```

`--dry-run` 会把渲染好的卡片存到 `storage/dry_run/*.json` 供你检查，**不发消息、不写任何状态文件**。改完配置先跑这个，别拿群当测试环境。

也可推到 GitHub 后用 Actions 定时运行（见 `.github/workflows/daily-push.yml`，默认北京时间每天 22:00）。**所有密钥走环境变量 / Secrets，绝不写进代码。**

需要配的 Secrets：

| Secret | 必填 | 说明 |
|--------|------|------|
| `FEISHU_WEBHOOK_URL` | ✅ | 飞书群机器人地址 |
| `AI_API_KEY` | ✅ | AI 模型密钥 |
| `TWITTER_COOKIES` | ⬜ | 抓 X 用，不填自动跳过 |
| `GITHUB_TOKEN` | ⬜ | Actions 自带，无需手动创建 |

> ⚠️ **别删 workflow 里的 `Persist state` 那一步。** GitHub Actions 每次都是全新容器，`storage/` 不写回仓库的话，机会库永远停在"第 1 次出现"、操盘手轮转会反复拆同一批人、去重历史每天清零。

> 💡 **说实话**：路线 A 更省心。你自己搭要准备 AI Key（花钱）、配 webhook、调试环境；直接进群，这些我都替你做了，而且每天的内容一样不少。除非你有定制需求（比如想加自己的信息源、推到别的平台），否则没必要重复造轮子。
